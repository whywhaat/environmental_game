# Экологическая игра «Город N»

Переговорная игра в Langflow: участники обсуждают финансирование проекта, распределяют ответственность и голосуют по итоговому соглашению. В репозитории находятся собственные компоненты Langflow и исходные материалы базы знаний.

## Запуск Langflow

Из корня репозитория выполните:

```powershell
docker compose -f langflow/docker-compose.yml up -d
```

Откройте `http://localhost:7860`. Compose запускает Langflow и PostgreSQL, подключает `langflow/custom_components` и сохраняет данные сервисов в томах Docker. Учётная запись администратора и пароли PostgreSQL заданы в `langflow/docker-compose.yml`; перед размещением сервиса в доступной другим среде замените их.

Готового экспортированного графа в текущей версии репозитория нет. Соберите граф в интерфейсе Langflow из компонентов каталога `my_components`:

1. Добавьте `Общий RAG · Chroma`, пять узлов `Player Agent` и `Two LLM Contract Game`.
2. Для каждого игрока выберите языковую модель, задайте имя, бюджет и стратегию. Укажите `player_id` из списка `city_administration`, `industrial_holding`, `regional_government`, `city_residents`, `environmental_ngo`: он нужен для подбора ролевых материалов RAG.
3. Соедините выходы `player` всех игроков со входом `players` оркестратора, а выход `config` узла RAG — со входом `rag_config`.
4. При необходимости добавьте `Настройки переговоров` и соедините `settings` со входом `settings` оркестратора. Подключите его выход `result` к `Report Controller`, затем выведите `result` в `Chat Output`.

Узел `OpenAI Compatible Model` по умолчанию использует `http://host.docker.internal:9090/v1` и модель `qwen3.8-9b-q4`; адрес и имя модели меняются в самом узле. Если API требует ключ, задайте `OPENAI_API_KEY` в окружении перед запуском Compose: эта переменная передаётся в контейнер. Для локального API без проверки ключа компонент использует значение `localai`. Узел `GigaChat Model` принимает токен во входном поле; для использования `GIGACHAT_ACCESS_TOKEN` его нужно отдельно передать в окружение контейнера.

Узел RAG содержит встроенный корпус и векторы. Для дополнительного семантического поиска ему нужен ключ во входном поле либо переменная `OPENAI_API_KEY` в контейнере; `TSARROUTER_API_KEY` тоже поддерживается компонентом, но Compose сейчас её не передаёт. Если при запуске узла отсутствует ChromaDB, установите в окружение Langflow `chromadb>=1,<2`. По умолчанию индекс хранится в домашнем каталоге контейнера; путь можно задать через поле `persist_directory`.

## Сценарий и результат

`Настройки переговоров` задают стоимость воды и тарифов (50 млн ₽), мониторинга (20 млн ₽), реконструкции (200 млн ₽) и максимум ходов торга (15). Оркестратор проводит вводные заявления, торг и поимённое голосование. Следующему игроку передаётся текущее состояние проекта без стенограммы предыдущих реплик; поиск RAG также не использует реплики прошлых ходов. `Report Controller` показывает итоговый проект и голоса, а при включённом `debug_mode` — последнее состояние игры. Текущие компоненты не сохраняют отдельные отчёты в `games/`.

Оркестратор требует подключённый RAG: игрок получает общие факты и материалы своей роли на всех этапах. На вступлении и в торге узел может дополнить их результатами семантического поиска. В данных результата поле `rag_retrievals` содержит идентификаторы обязательных и найденных фрагментов, роль и статус поиска. Читаемые исходные материалы находятся в [rag_docs_gorod_N/00_README.md](rag_docs_gorod_N/00_README.md); встроенный корпус узла RAG хранится непосредственно в `langflow/custom_components/my_components/rag.py`.

## Состояние репозитория

Самостоятельный пакет `negotiation_mvp`, пример его конфигурации, прежний экспорт графа и тесты удалены. Оставшиеся `langflow/smoke_run.py`, `component_smoke.py` и `build_demo_flow.py` ссылаются на удалённые файлы, поэтому сейчас не служат командами проверки или сборки графа.

Проверить синтаксис Compose без запуска контейнеров можно командой:

```powershell
docker compose -f langflow/docker-compose.yml config --quiet
```
