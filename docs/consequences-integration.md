# Подключение модели последствий

Модель принимает готовый итог игры и возвращает последствия для города и участников. Команда ядра отвечает за переговоры, значения условий и голосование; наш модуль рассчитывает исполнение, состояние города, исход и текст итога.

## Быстрый запуск пакета

Распакуйте архив и откройте терминал в его корне. Для расчёта нужен Python 3.11+; сторонние библиотеки и API-ключи не требуются.

```bash
python -m consequences_model examples/consequences/open_river.json --json
python -m consequences_model examples/consequences/each_for_self.json --json
```

Без `--json` CLI выводит подробный отчёт для разбора. Одноабзацный текст для игрока доступен как `herald_text` в JSON или через Python API:

```python
import json
from pathlib import Path
from consequences_model import forecast

game_result = json.loads(Path("examples/consequences/open_river.json").read_text(encoding="utf-8"))
result = forecast(game_result)
print(result["herald_text"])
```

Папка `consequences_model` должна находиться в пути импорта приложения, например рядом с его точкой входа. Для другого движка достаточно сформировать тот же входной словарь; Langflow для Python API не нужен.

## Вход: готовый итог игры

В общей версии от 04.11.2026 используется structured-ядро `review@05769da` и узел `NegotiationGame-main`. Ответы `PlayerTurn` обрабатываются внутри ядра; вход модели последствий остаётся готовым `Data.data` в рублях.

Если вход содержит `status`, расчёт выполняется только при `status="completed"`. Для `running`, `failed` и `cancelled` API и CLI возвращают `status="skipped"`, исходный статус в `game_status`, текст о незавершённой игре в `herald_text`, статусный `report` и пустой `herald_prompt`. Отчёт различает продолжающуюся, прерванную из-за ошибки и отменённую игру; подробности самой ошибки остаются в промежуточном отчёте ядра. Полей `outcome`, `protocol`, `paid` и других последствий в таком результате нет. Langflow показывает статусное сообщение без изображения. Отсутствующий `status` поддерживается для сохранённых JSON прежнего ядра.

В `forecast(...)` передаётся содержимое `Data.data`, а не оболочка `Data` и не объект `{"data": ...}`. Полный пример принятого протокола — [open_river.json](../examples/consequences/open_river.json), непринятого — [each_for_self.json](../examples/consequences/each_for_self.json). Все десять примеров синтетические и перечислены в [manifest.json](../examples/consequences/manifest.json).

Дополнительно включены [два компактных JSON реальных партий](../examples/integration/README.md) из `Vlad's_branch@10a5c68` от 30.10.2026, локально сыгранных с GigaChat 03.11.2026. Их можно повторно рассчитать без сети:

```bash
python -m consequences_model examples/integration/vlad_10a5c68_accepted.json --json
python -m consequences_model examples/integration/vlad_10a5c68_rejected.json --json
```

В проверенной версии ядро принимает протокол по большинству голосов; закрытая смета проверяется отдельно. Поэтому первый пример принят с дефицитом 10 млн ₽. Модель сохраняет `consensus_reached`, не пересчитывает голосование и не добавляет недостающие взносы. Эти два примера закрепляют совместимость с указанным коммитом; они не заменяют проверку других стратегий и версий ядра.

Для корректного расчёта передавайте заполненный итог со следующими полями:

| Поле | Содержание |
| --- | --- |
| `total_cost` | Положительная стоимость проекта в рублях; для модели это основная смета. |
| `consensus_reached` | Булев итог принятия протокола, рассчитанный ядром. Модель использует этот флаг. |
| `players` | Профили пяти ролей: стабильный `id`, уникальное `name`, `budget` в рублях. |
| `state.players[имя].contribution` | Заявленный взнос в рублях, не проценты и не миллионы; `0`/`null` означает отсутствие взноса. |
| `state.players[имя].spent_on_levers` | Уже учтённые ядром расходы этой роли на условия, в рублях. Учитываются вместе со взносом при проверке бюджета. |
| `state.levers` | Значения условий протокола, перечисленных ниже. |
| `voting_summary.records` | Записи `player` = точное имя из профиля, `vote` = `ЗА`, `ПРОТИВ` или `ВОЗДЕРЖАЛСЯ`. |

Стабильные идентификаторы ролей: `city_administration`, `industrial_holding`, `regional_government`, `city_residents`, `environmental_ngo`. Имена можно менять, но ключи `state.players` и `voting_summary.records[].player` должны совпадать с `players[].name`. Сопоставление роли по тексту имени не выполняется.

Отсутствующая запись голоса считается воздержанием. Неизвестные роли, игроки, голоса и условия могут давать `warnings`; недопустимое значение известного условия заменяется значением по умолчанию. Это не полная проверка входа: обязательные поля и числовые типы должна обеспечивать интеграция.

Поля `report`, `history`, `rag_retrievals`, `files`, `total_money`, `deficit`, `state.players[имя].share` и `players[].prompt` для расчёта не нужны. Доли определяются по взносам и `total_cost`. Старый результат CLI-движка с `final_state`, `accepted` и `parameters` имеет другой формат; этот модуль рассчитан на формат оркестратора Влада.

### Условия протокола

| Ключ `state.levers` | Значения | По умолчанию |
| --- | --- | --- |
| `timeline` | Целое число месяцев, 24–48 | `36` |
| `plant_mode` | `"100%"` или `"70%"` | `"100%"` |
| `guilt` | `"shared"`, `"holding"`, `"city"` | `"shared"` |
| `tariffs_freeze` | `true` / `false` | `false` |
| `tax_relief` | `true` / `false` | `false` |
| `open_sensors` | `true` / `false` | `false` |
| `protest_moratorium` | `true` / `false` | `false` |
| `water_supply` | `true` / `false` | `false` |

## Выход: данные и представление

| Поле результата | Для чего использовать |
| --- | --- |
| `herald_text` | Готовый текст игроку одним абзацем: события, деньги, сроки и показатели. Без методических вставок. |
| `outcome.id` | Стабильный ключ исхода для выбора иллюстрации или экрана. |
| `outcome.name`, `outcome.description` | Название и описание исхода. |
| `paid`, `promised_months`, `commissioning_month` | Исполненные взносы в рублях, обещанный срок и фактический месяц ввода; `null` — не введены за 10 лет. |
| `execution` | Исполнение обязательств: полностью, частично или нет. |
| `state` | Состояние пяти подсистем через год, при вводе и через 10 лет. |
| `fates` | Цели участников и признаки их достижения. |
| `explanation`, `report`, `warnings` | Подробный разбор, источники правил и диагностика для ведущего/разработчика. |
| `herald_prompt` | Необязательный промпт для отдельного LLM-узла. Готовый `herald_text` получается без LLM. |

Для интерфейса игрока выводите `herald_text`, а не весь JSON или подробный `report`. Бинарных изображений в результате Python API нет.

## Подключение в Langflow

Проверено с Langflow/lfx 1.12.5. В [автономном компоненте](../langflow/custom_components/my_components/ConsequencesModel.py) расчёт встроен; установка Python-пакета проекта на сервер не требуется.

1. Для проверки импортируйте [Consequences_demo.json](../langflow/Consequences_demo.json). В Playground отправьте `1`–`10`, название или id исхода.
2. В компоненте «Модель последствий» загрузите три PNG в поля соответствующих исходов. Файлы из ZIP не становятся файлами хранилища Langflow автоматически.
3. Для реальной игры добавьте этот же компонент и соедините `NegotiationGame-main.result` с его входом `game_result`.
4. Соедините выход `newspaper` («Газета») с `ChatOutput.input_value`. Получится изображение и отдельный читаемый абзац в одном сообщении.

Выходы `forecast`, `report` и `herald_prompt` доступны отдельно. Демонстрационный flow содержит только выбор проверочного JSON, модель и чат; это не сыгранная партия. Исходный flow команды и её код в архив не входят.

## Проверка целостности и пересборка

Корневой `manifest.json` архива содержит SHA-256 каждого файла пакета, кроме самого манифеста. В пакет включены только наши исполняемые модули, примеры, изображения, компонент, стенд и инструкции. Из реальных партий включены только описанные выше компактные JSON; полные локальные результаты и окружение не переносятся.

В исходном репозитории архив собирается командой:

```bash
python -m consequences_model.build_bundle
```

Результат — `dist/consequences-model.zip`. После изменения модели или примеров сначала пересоберите компонент и flow штатными сборщиками, затем архив; проверка согласованности останавливает упаковку устаревших экспортов. В самом архиве лежит исполняемый пакет, а не инструменты разработки и код ядра игры.
