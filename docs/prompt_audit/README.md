# Аудит инструкций переговорной системы

Дата: 20.10.2026. Статус: отчёт статического аудита; рекомендации не утверждены. Область изменений — только `docs/prompt_audit/`. Действующие промпты, приложение, flow, корпус, конфигурации и регламент не исправлялись.

Оценка текущего Python-контура — **51/100**. Основные ограничения связаны с достоверностью итогового документа, состоянием обязательств и несовпадающими версиями процесса. Экспортированный flow имеет дополнительные критические дефекты и оценивается отдельно. Наличие вызова в исходниках подтверждает маршрут использования, но не доказывает, что именно эти исходники загружены в работающий Langflow.

## Метод и границы доказательств

Изучены дерево репозитория, все модули `config/prompts/`, все восемь прикладных компонентов, встроенные тексты и код узлов `LF_Agent_RAG.json`, девять компактных RAG-документов, фактические 159 записей корпуса, пять паспортов и критерии голосования, игровые документы, DoR/DoD и аналитическая модель `docs/agent_consistency/`. Поиск включал `SystemMessage`, `HumanMessage`, `invoke`, поля инструкций, шаблоны, инструкции в Markdown/YAML/JSON и программную сборку; именами файлов с `prompt` поиск не ограничивался. `DeveloperMessage` в прикладных маршрутах не найден. Внешние инструкции провайдера и состояние запущенного сервиса неизвестны.

Выполнены чтение AST, проверка графа связей, сравнение строк config/flow, декодирование корпуса без исполнения его содержимого, существующие тесты и короткие локальные пробы функций. Сетевых запросов к моделям, embeddings API и работающему Langflow не было. PDF и правовые первоисточники повторно не проверялись: оценивается способ использования имеющихся выдержек, а не истинность актуального права. Юридические выводы не делаются.

Различаются три вида находок: **подтверждённый дефект/расхождение** — виден в тексте или вычислении; **потенциальный риск** — существует маршрут сбоя, но поведение LLM не измерено; **недостаток информации** — например, какая редакция развёрнута и кем утверждена. Отсутствие проверки не доказывает, что модель обязательно нарушит правило. Отсутствие механизма из аналитического проекта не является само по себе нарушением утверждённого регламента.

`approved=false` в [game_config.yaml](../../ecological_simulator_knowledge/04_game_rules/game_config.yaml) и незаполненные решения [DEC-01–10](../agent_consistency/decision_register.yaml) сохраняют силу как сведения об утверждении. Ни одно предложение из этого аудита не получает статус approved. Существование противоречащих текстов фиксируется независимо от того, какую редакцию команда позднее выберет.

## Единица учёта и статусы использования

Реестр содержит **68 мест определения инструкций/шаблонов**, а не 68 независимых агентов или уникальных текстов: 38 ключей общего config, 9 заполненных текстовых полей flow, 15 встроенных блоков flow, пять встроенных значений по умолчанию Player и одно поле System Message общей модели. Контейнер `judge_events` считается одним блоком с девятью событиями; условные ветви одного шаблона — одним блоком. Повторы в разных местах считаются отдельно, поскольку могут рассинхронизироваться. Данные профиля и RAG-записи учитываются отдельно как контекст, а не прибавляются к числу промптов. Пустые переопределяемые поля не создают нового промпта.

«Используется» означает подтверждённое потребление на указанном пути при его запуске. «Не используется» сопровождается причиной: нет обращения загрузчика, текст перекрыт или поле не читается. Для выключенных `active=false` узлов указано «не используется в сохранённом flow; используется при включении». «Неизвестен» применяется к внешней конфигурации и неподтверждённому наследуемому поведению. Реальные запуски ни для одного пути не подтверждены этим аудитом.

## Оценки

Каждая запись реестра получает экспертную оценку пригодности **в её месте использования**, не за объём текста. Для фрагмента оценивается его вклад в составной промпт, поэтому оценка краткого System не равна оценке всей роли. Оценки не являются результатами бенчмарка, вероятностью успеха или баллами игрового скоринга. Для неиспользуемых блоков оценивается предполагаемая пригодность с пониженной уверенностью.

Для ролей десять критериев по 0–10: идентичность, интересы, полномочия, ресурсы, история позиции, содержательный диалог, процедура/передача слова, доказательность, различение согласия/обязательства, устойчивость. Для судьи: независимость, регламент, факты, полномочия, ресурсы, последовательность, обязательства, протокол, вмешательство, объяснение. Для оркестратора: очередь, этапы, состояние, валидация действий, финансы, голоса, документ, доступ, восстановление, согласованность инструкций. Отдельные шаблоны оцениваются по применимым критериям с нормированием до 100; основание оценки указано в реестре.

Общий балл относится к текущему Python-контуру: средняя оценка пяти ролей 54,4 × 50% + председатель 50 × 20% + оркестратор 43 × 20% + RAG-контур 50 × 10% = 50,8, округлённо **51**. Веса выбраны для этого аудита, не утверждают продуктовую метрику. Вариант flow показан отдельно и не смешан с исходниками.

## Воспроизводимые проверки

Существующий набор `tests/test_meeting_protocol.py` запущен через `unittest.defaultTestLoader.discover('tests')` в локальном Python 3.12 с `-B -X utf8`: **19 тестов, 18 успешных, 1 failure, 0 errors, 0 skipped**. Не проходит `test_exported_flow_prompts_match_prompt_config`, первое сравнение на строках 176–177: экспортированный регламент отличается от `meeting_rules`. Дальнейшее сравнение администратора в этом тесте не достигается; его несовпадение отдельно подтверждено сравнением строк.

Тесты используют AST-загрузку классов, фиктивные интерфейсы и модели; это не интеграционный тест Langflow и не проверка переговорного качества LLM. Дополнительные пробы выполнялись в памяти, без добавления тестового кода в репозиторий:

| Проба | Наблюдаемый результат |
|---|---|
| Текущий `_parse`: 1000; 1001; `5 руб` | 1 000 000 000 руб.; 1001 руб.; 5 000 000 руб. |
| Нераспознанный бюллетень `нужно уточнить проект` | Python: ВОЗДЕРЖАЛСЯ; flow: ЗА |
| Flow: `SET B Взнос 2000` от A при нулевом бюджете B | `valid=True`, `player=B`, 2000 руб.; в коде далее прямое применение |
| История пуста, принятый итог передан рендереру Python | В текст включаются 24 месяца и прочие фиксированные условия |
| Взносы 999 999 500 руб. | `_render_state` пишет «ДЕФИЦИТ: 0 руб.» |
| 3/5 и 999 900 000 руб. | Формула flow допускает принятие; `MeetingJudgeService.decide` — нет |
| Корпус `rag.py` и JSONL | 159 записей, равенство разобранных JSON; два фрагмента содержат старые ИЕ |

Строки в отчёте относятся к текущим файлам рабочего дерева. Для flow указаны физическая строка JSON, ID узла, JSON Pointer и, где нужно, строки декодированного Python. Это позволяет найти дефект без вывода гигантской строки кода или секретов.
