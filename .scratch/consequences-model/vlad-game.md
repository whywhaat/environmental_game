# Игра Влада: что модель последствий получит на входе

Status: needs-triage

Факты для перехода модели на игру Влада (решение команды 23.10: игра Влада основная). Снято с `origin/Vlad's_branch` на коммите `ebe77fb` (23.10, «Пофиксил баги, но есть проблемы с парсингом»); 28.10 перепроверено на `1f97df7` (27.10, правки RAG и отчёта, в ветку коммитит и Олег): ключи выхода оркестратора те же. Ветка в работе, формат может поменяться.

## Где игра

- Langflow-оркестратор `TwoLLMContractGame` в `langflow/custom_components/my_components/dialog.py` — свой движок на три фазы: заявления, торг (`max_rounds`, по умолчанию 15), поимённое голосование. Ядро `negotiation_mvp` он не использует: оно осталось для командной строки, там Влад добавил те же условия как `parameters.*`.
- Flow `langflow/Negotiation_MVP_5_players.json`: 11 узлов. Модель у каждого PlayerAgent своя (поле выбора модели и API key), отдельных узлов моделей нет. Связь `LanguageModelComponent-converter → TwoLLMContractGame.converter_model` ведёт в поле, которого в оркестраторе нет.
- Файлов игры оркестратор не пишет (`files: {}`), `result.json` нет.

## Выход оркестратора `Data.data`

`report`, `history`, `rag_retrievals`, `players`, `state`, `voting_summary`, `consensus_reached`, `total_money`, `total_cost`, `deficit`.

- `players` — профили PlayerAgent без `llm`: `id` (роль), `name`, `budget` (в рублях: PlayerAgent умножает «Бюджет, млн ₽» на миллион), `prompt` и др. Сопоставление имя → роль только через этот список.
- `state.players[<имя>]` — `contribution`, `share` (% сметы), `spent_on_levers`. Ключ — имя игрока, не роль.
- `state.levers[<id>]` — значение условия. Заполнено значениями по умолчанию с начала игры: согласованное условие от несогласованного отличается только по `history` (у хода `action.applied[]` с `kind: "LEVER"`).
- `voting_summary.records[]` — `player` (имя), `vote` ∈ «ЗА» | «ПРОТИВ» | «ВОЗДЕРЖАЛСЯ», `comment`; плюс `votes_for/against/abstain`, `majority_threshold`, `passed`.
- Протокол принят (`consensus_reached`): голосов «ЗА» не меньше большинства и дефицит не больше 100 тыс. ₽.
- Смета 270 млн ₽ одной суммой (`DEFAULT_PROJECT_COST` или настройки). Компонентов с ответственными нет.

## Условия протокола (`levers`)

Менять условие может только владелец, иначе `LEVER_REJECTED`.

| id | Что | Значения, по умолчанию | Владелец |
|---|---|---|---|
| `guilt` | Признание вины за аварию | shared / holding / city; shared | Региональная власть |
| `plant_mode` | Режим работы комбината | 100% / 70%; 100% | Промышленный холдинг |
| `timeline` | Срок реконструкции, мес. | 24–48; 36 | Промышленный холдинг |
| `tariffs_freeze` | Заморозка тарифов ЖКХ | да/нет; нет | Администрация города N |
| `tax_relief` | Налоговые льготы предприятию | да/нет; нет | Региональная власть |
| `open_sensors` | Открытые эко-датчики 24/7 | да/нет; нет | Экологическая организация (НКО) |
| `protest_moratorium` | Мораторий на протесты и иски | да/нет; нет | Инициативная группа жителей |
| `water_supply` | Гарантия питьевой воды жителям, 20 млн ₽ | да/нет; нет | Администрация города N |

## Расхождения с текущей моделью

- Нет ответственных за компоненты: правила исполнения по ответственному, потолок «частично» для жителей и НКО и подъём от независимого мониторинга не на что опереть.
- Мониторинг стал условием НКО «открытые датчики», вода — условием администрации с ценой.
- Срок реконструкции теперь предмет переговоров (раньше допущение 36 мес.).
- Новые условия без опоры в модели: вина, режим комбината, тарифы, налоговые льготы, мораторий на протесты.
- В глоссарии «рычаг» — инструмент влияния, а у Влада «рычаги» — условия протокола: термин нужно развести.
- Голос «ВОЗДЕРЖАЛСЯ» есть явно; принятие зависит и от дефицита.
