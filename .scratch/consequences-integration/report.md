В локальном провайдере для GigaChat потребовались две транспортные адаптации. Сначала API отклонил несколько SystemMessage с HTTP 400; весь их текст теперь объединяется в одно первое сообщение с сохранением порядка. Следующий запрос показал, что SDK не превращает plain JSON Schema автоматически в подходящую функцию: HTTP 422. Локальный адаптер разворачивает ссылки через `dereference_refs` и преобразует схему через `convert_to_openai_function` в `name/parameters`. Поля и ограничения игрового контракта сохраняются; изменения остаются в локальном провайдере, а не в ядре. До повторного запроса проверены структура функции, отсутствие `$ref/$defs`, сохранение всех полей и системного текста на фиксированном ответе SDK без сети.

Общий отслеживаемый JSON использует штатные модельные входы PlayerAgent. Native-провайдер с путём к локальному `.env` находится только в установленном локальном flow и игнорируемом скрипте; ключ не попадает в переносимый экспорт или архив.

**Ограничение качества переговоров:** восемь ходов получили `invalid_response` после неудачного исправления. Модели меняли условия чужой роли, адресовали требование себе либо принимали требование без явного собственного обязательства. Ядро атомарно отклонило эти ходы; взносы в итоговом состоянии остались нулевыми. Это наблюдение об ответах участников, а не сбой передачи JSON или расчёта последствий.
