## Поведение

- Исходники `negotiation_game`, собранный `dialog.py`, асинхронные structured-output вызовы, права ролей и правило принятия по большинству остаются из review. Старые ядро и текстовый конвертер не возвращаются.
- Сохраняются наша детерминированная модель, два исправления достижения целей участников, десять исходов, один абзац `herald_text` без методических вставок, три PNG и механизм выбора изображения только по `outcome.id`. Сохраняются стенд, реальные примеры и переносимый пакет.
- Для `status=running/failed/cancelled` последствий нет: публичный `forecast` возвращает `status=skipped`, исходный статус в `game_status`, сообщение о незавершённой игре, статусный отчёт с различием продолжения/ошибки/отмены и указанием смотреть промежуточный отчёт ядра, пустой промпт; поля исхода/числового прогноза отсутствуют. Все выходы Langflow, включая `newspaper`, поддерживают это поведение, изображения не читаются. При отсутствующем `status` сохраняется поддержка старых завершённых JSON. CLI и API имеют одинаковую защиту.
- Сборщик последствий подключает актуальный `NegotiationGame-main.result` к `game_result`, а `newspaper` — к ChatOutput. Весь базовый игровой граф копируется без изменения его кода и настроек. Настройки обоих графов соответствуют базовому review, включая бюджет НКО 10 млн ₽. Непустое сохранённое `embedding_api_key` очищается в базовом экспорте перед пересборкой; ключи задаются отдельно в локальном окружении.
- Уже импортированные пользовательские flows не перезаписываются. Для проверки создаются отдельные локальные flows с native GigaChat на существующем сохранённом Authorization Key. В реальном проверочном запуске — пять ходов торга и сохранение полного результата; код переговоров совпадает с review. Переговоры и последствия проверяются одной цепочкой до ChatOutput.
- На локальном native-провайдере системные сообщения объединяются в одно с сохранением всего текста и порядка, а JSON Schema преобразуется средствами LangChain в функцию с `parameters` и развёрнутыми ссылками. Игровые поля, ограничения и валидация ядра сохраняются. Это настройка локального транспорта; общий экспорт продолжает использовать штатный провайдер PlayerAgent.
- До живой партии повторяются два сохранённых реальных результата `10a5c68` через нашу модель и чат. В названии/отправителе явно отмечается повтор сохранённых партий. Проверяются исходы, деньги, сроки, один абзац и соответствие PNG; при отсутствии картинки соответствующего исхода остаётся текст.
- Не устанавливаются новые зависимости, ключи не выводятся, push и отправка пакета другим людям не входят в задачу. Локальные credentials/DB/сырые партии остаются в игнорируемом `games`.

Используются уже согласованные публичные границы: `forecast`, CLI из распакованного пакета, выходные методы Langflow-компонента, `NegotiationGame.run_chat → Data.data → forecast`, готовый граф и API запуска/истории Playground. Проверка свежего сценария с дефицитом и большинством подтверждает принятие флага ядра без пересчёта в модели.

После пересборки сравниваются встроенный код с обоими пакетами и исходные игровые компоненты с review; выполняются отдельные тесты по ходу работы, полный набор один раз в конце и native LF transport/lifecycle проверки.
