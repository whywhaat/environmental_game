# AGENTS.md

Единый источник инструкций для coding agents в этом репозитории. `CLAUDE.md`
импортирует этот файл; общие правила обновляйте только здесь.

## Область работы

- Общайтесь с пользователем по-русски. Отделяйте факты от гипотез и рекомендаций.
- Исследуйте только область задачи. Не превращайте точечный вопрос в полный аудит.
- При исследовании и ревью не меняйте файлы. Изменения выполняйте по явному поручению;
  перед существенными изменениями кратко объясните план. Не делайте побочный рефакторинг.
- Перед командами, меняющими данные, окружение или внешние системы, согласуйте действие,
  если оно ещё не разрешено пользователем. Отдельно согласуйте установку зависимостей,
  изменения инфраструктуры, операции с реальной БД, удаление файлов, коммиты и push.
- Не раскрывайте секреты и не отправляйте данные во внешние сервисы без согласования.
- Документацию сверяйте с кодом, тестами и конфигурацией. Расхождения фиксируйте явно.
- В ревью указывайте файл и строки, механизм проблемы и доказательство. Используйте
  `CONFIRMED`, `LIKELY`, `HYPOTHESIS`, `NOT AN ISSUE`; для подтверждённых дефектов —
  серьёзность `Critical / High / Medium / Low`. Не исправляйте их без поручения.
- После изменений сообщайте, что изменено, какие проверки выполнены, что не проверено
  и какие риски остались. Не называйте незапущенные тесты пройденными.

## Контекст и точки входа

Проект — учебная игра «Экологическая ситуация в городе N»: пять ролей договариваются
о реконструкции очистных и голосуют за протокол. Модель последствий рассчитывает
состояние города и судьбы участников на горизонте 10 лет.

Перед исследованием прочитайте [GLOSSARY.md](GLOSSARY.md) и относящиеся к задаче
[ADR](docs/adr/). Правила работы с ними: [domain.md](docs/agents/domain.md).
Учитывайте статус ADR: ADR-0002 и ADR-0003 заменены ADR-0004.

В репозитории две реализации переговоров с разными контрактами результата:

| Область | Где начинать | Особенности |
| --- | --- | --- |
| Основная игра в Langflow (игра Влада, ADR-0005) | `negotiation_game/langflow_component.py`, класс `NegotiationGame`; `negotiation_game/schemas.py`, `rules.py`; `langflow/Negotiation_MVP_5_players.json` | Схемы и правила отделены от адаптера Langflow (ADR-0006). Результат содержит `state`, `players`, `voting_summary`, `consensus_reached`; условия протокола принадлежат ролям. |
| Самостоятельный движок (игра Олега) | `negotiation_mvp/cli.py`, `engine.py`, `core.py`; `example_config.json` | Результат содержит `final_state`, `final_scores`, `votes`, `accepted`; используются ответственные за компоненты сметы. `langflow_bridge.py` — адаптер этого движка. |
| Модель последствий | `consequences_model/protocol.py`, `model.py`, `state.py`, `catalog.py`, `report.py` | Принимает результат основной игры Langflow, а не результат `negotiation_mvp` (ADR-0005). Расчёт детерминированный, LLM только объясняет результат (ADR-0001). |
| Flow с последствиями | `consequences_model/build_flow.py`; `langflow/Negotiation_MVP_with_consequences.json` | Добавляет модель последствий и ChatOutput к базовому flow. |
| RAG | `langflow/custom_components/my_components/dialog.py`, `rag.py`; `negotiation_mvp/rag.py`, `rag_policy.py` | Реализации Langflow и самостоятельного движка проверяйте отдельно. Корпус: `full_embeddings.jsonl`, материалы: `rag_docs_gorod_N/`. |
| Промпты и запуск | `config/`, `langflow/docker-compose.yml` | Сначала проверьте, какой код и какие настройки использует выбранная реализация. |

Не переносите выводы о формате, правилах или RAG одного движка на другой без проверки.
README описывает оба варианта, но не содержит всей актуальной карты компонентов.

## Исходники и собранные файлы

- `langflow/custom_components/my_components/dialog.py` — генерируемый файл основной игры.
  Правьте `negotiation_game/schemas.py`, `rules.py`, `report.py`, `run_store.py` и `langflow_component.py`, затем
  выполните `python -m negotiation_game.build_component`: команда обновляет компонент
  и его код в обоих JSON flow, сохраняя настройки и связи. Langflow и API для сборки не нужны.
  Проверка: `python -m unittest discover -s tests -p 'test_structured_turns.py'`.
  `run_chat` и вызовы моделей асинхронные: не заменяйте `ainvoke`/`asyncio.sleep`
  на блокирующие вызовы. Прогресс и частичные отчёты сохраняются в `NEGOTIATION_GAMES_DIR`
  (по умолчанию `games/` относительно рабочего каталога процесса Langflow).
  Транспортная проверка на установленном Langflow: `python tests/verify_lf_lifecycle.py`;
  она открывает временный локальный HTTP-сервер, не вызывает GigaChat и не проверяет генерацию модели.
- `langflow/custom_components/my_components/ConsequencesModel.py` — генерируемый файл.
  Правьте пакет `consequences_model/`, затем пересобирайте компонент командой
  `python -m consequences_model.build_component` (ADR-0004).
- После изменения компонента последствий пересоберите flow с последствиями через
  `consequences_model/build_flow.py`. Сборка требует `lfx`; команда с указанной версией
  находится в докстринге скрипта. Не устанавливайте зависимость автоматически.
- JSON flow содержит собственный код узлов. Изменение `.py` компонента само по себе
  не обновляет код в JSON. При правках проверяйте исходник и соответствующий экспорт.
- `langflow/build_demo_flow.py` строит базовый граф из шаблонов компонентов и
  `demo_config.json`. Не запускайте его вслепую: сопоставьте собираемый граф с текущим
  экспортом, чтобы не потерять узлы и настройки.

## Запуск и проверки

Команды ниже выполняются из корня репозитория. Это точки входа из исходников,
а не утверждение, что окружение настроено или проверки уже прошли.

- Langflow и PostgreSQL описаны в `langflow/docker-compose.yml`; порт Langflow — 7860.
  Запуск: `docker compose -f langflow/docker-compose.yml up -d`.
  Команда запускает сервисы и может скачать образы; выполняйте её только в рамках
  согласованной работы с окружением.
- Самостоятельный движок: `python -m negotiation_mvp --config example_config.json`.
  Нужны `PLAYER_MODEL`, `CONVERTER_MODEL` и настройки API из `negotiation_mvp/llm.py`.
  Запуск вызывает LLM API и записывает отчёты в `games/`.
- Прогноз по сохранённому результату основной игры:
  `python -m consequences_model <game-result.json>`; `--json` выводит полный прогноз.
  Ожидается содержимое `Data.data` оркестратора, не произвольный JSON отчёта.
- Для выбранной области используйте `python -m unittest discover -s tests -p '<имя файла>'`:
  `test_mvp.py`, `test_langflow_bridge.py`, `test_langflow_actions.py`,
  `test_langflow_rag_roles.py`, `test_rag_policy.py`, `test_consequences_model.py`.
  Полный набор: `python -m unittest discover -s tests`.
- Тесты последствий проверяют соответствие пакета, собранного компонента и flow;
  тесты Langflow также исследуют код узлов внутри JSON. Не считайте любое падение
  дефектом реализации, пока не проверили контракт теста и актуальность экспорта.
- `langflow/smoke_run.py` вызывает LLM через адаптер `negotiation_mvp` и пишет файлы.
  Это не полная проверка основного оркестратора. Smoke-скрипты сначала читайте;
  не запускайте их как заведомо безопасные unit-тесты.

## Тикеты и спецификации

- Локальный трекер: `.scratch/<фича>/spec.md`, отдельные тикеты —
  `.scratch/<фича>/issues/<NN>-<slug>.md`. Подробности: [issue-tracker.md](docs/agents/issue-tracker.md).
- Для triage используются `needs-triage`, `needs-info`, `ready-for-agent`,
  `ready-for-human`, `wontfix` в строке `Status:`; см. [triage-labels.md](docs/agents/triage-labels.md).
  У Wayfinding отдельный жизненный цикл, описанный в `issue-tracker.md`.
- `scratch/` и `.scratch/` — разные каталоги; не считайте вспомогательные скрипты
  из `scratch/` актуальными инструкциями по запуску или изменению проекта.
