# Проверка библиотеки пошаговых переговоров

## Объём

Основной комплект — добавленный каталог `08_negotiation_examples/step_by_step/`: 10 сценариев, обзор, правила очередности, передача архитектору, этот отчёт, YAML-контракт и JSON сообщений. Итого **16 новых файлов: 14 Markdown, 1 YAML, 1 JSON**. По дополнительному указанию пользователя денежные показатели также обновлены в существующих связанных документах и демонстрационной ресурсной YAML-карточке. Новые исполняемые файлы, зависимости и тесты приложения не добавлены.

Все разговоры синтетические; выводы ниже не являются подтверждением настоящих бюджетов, полномочий, лабораторных данных, юридического механизма или готовности приложения.

## Автоматические проверки содержимого

Проверки выполнены одноразовыми локальными командами без добавления проверочного кода в репозиторий:

- JSON разобран стандартным JSON-парсером; найдены **10 сценариев и 125 сообщений** с 11 обязательными полями.
- Для каждого сообщения проверены пять непустых абзацев Markdown, точное совпадение первых четырёх с содержательными полями JSON и точное соединение всех пяти в `public_speech`.
- Проверены непрерывные номера ходов, пять допустимых ID, фиксированная очередь и `next_speaker`. Для каждого агента проверено постоянство точной завершающей фразы из контракта; после НКО адресат — `orchestrator`.
- В JSON представлены 9 типов действий: propose, object, counterpropose, request_evidence, clarify, confirm_own_commitment, correct, vote, decline_reconsideration. Решения судьи и служебные реплики не смешаны с публичными сообщениями.
- Проверены локальные Markdown-ссылки и якоря, а также **500 `source_refs`** JSON; цели существуют. Ссылки на исходные файлы проверяют их наличие, а не актуальность реальных правовых сведений.
- Проверены счётчики: предел 30 ходов не превышен ни в одном примере; сценарий 10 учитывает 10 исходных ходов плюс 5 новых, сценарий 06 — 10 до голосования плюс 5 отказов от повтора. Сверка и голосование в лимит не включены.
- Проверены пять голосов по одной версии в каждом из двух полных примеров: 05 — **4/0/1**, 06 — **2/3/0**. Судья не включён в электорат.
- Арифметика: 200+450+350 = 1000 млн руб. и 100+150+550+100+100 = 1000 млн руб.; для v2 сценария 10: 200+400+350 = 950 млн руб. и 100+150+500+100+100 = 950 млн руб. Доли в положительных и исправленных предложениях находятся в демонстрационных пределах; намеренное превышение 600 млн руб. в 07/1 отклонено. Активированный ресурс не объявлен положительным.

## Git и сохранность

Рабочая ветка — `Analyst_branch`. Изменения отслеживаемых файлов ограничены документацией базы знаний и её демонстрационной ресурсной карточкой: суммы, единицы, арифметика, определения и пояснения. Новый каталог библиотеки остаётся неотслеживаемым до решения о коммите. Проверены `git diff --check` для существующих документов и `git diff --no-index --check` для новых; удаления документов отсутствуют. Python-код, промпты, исходный flow, индексы и матрица доступа не менялись. Для просмотра неотслеживаемых файлов нужен `--no-index` или просмотр содержимого: обычный `git diff` до `git add` их не отображает. Индекс Git не изменялся; коммит и push не выполнялись.

## Дополнительная проверка денежных единиц

Базовый учебный пакет — 1000 млн руб.; условное распределение — 200/450/350 млн руб., пределы — 200/500/400 млн руб., резерв — 100 млн руб. В структурированной ресурсной карточке суммы записаны в рублях: 1000000000, 200000000, 450000000 и 350000000. В сценарии пересмотра новый пакет — 950 млн руб. = 200+400+350 млн руб. Единицы и пояснения обновлены также в старых примерах, паспортах, правилах судьи и глоссарии. JSON повторно синхронизирован с полными текстовыми репликами. Номера ходов, даты D+/T+, идентификаторы, лимит 30 ходов и итоги голосований сохранены.

## Ограничения и противоречия

YAML-контракт просмотрен вручную на структуру, типы, обязательные поля и согласованность перечислений с JSON. Полный разбор YAML сторонним парсером не выполнялся: в доступном Python-окружении отсутствует PyYAML. JSON разбирался программно. Нельзя выдавать ручную сверку YAML за результат PyYAML или формальную JSON Schema-валидацию: отдельная JSON Schema здесь не создавалась.

Оставшиеся противоречия документационной модели с кодом и экспортированным flow описаны в [передаче архитектору](architect_handover.md#contradictions). Денежные единицы документации согласованы с рублями; различия раундов, очередности и голосования не устранены. В предварительном обзоре существующего проекта было 18 успешных тестов из 19; падал тест соответствия регламента flow промпту. В рамках этой документационной задачи существующие тесты повторно не запускались; интеграция с реальными моделями, RAG, ACL и Docker не тестировалась.

## Решение по комплекту

Библиотека пригодна для передачи архитектору как аналитические примеры и ожидаемые результаты. Она **не активирует регламент и не подтверждает готовность программного симулятора**. Перед использованием в запуске нужны согласование модели раундов и финансов, допустимого типа результата, очереди и прав на контекст, а затем отдельные интеграционные проверки.

Предлагаемое название коммита: `docs: add step-by-step negotiation examples for five agents`.
